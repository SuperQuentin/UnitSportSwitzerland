# Adventure places: POI catalogue, discovery, fog of war and the Swiss Atlas

Status: **planned**. Tracking issue: #1224 (overview: #1228).

One of five Adventure plans (phases 1 and 2), written together: `adventure-objectives` (progress
store, events, quests, `AdventureLog`), `adventure-navigation` (compass, pins, tracked marker, travel
network), `adventure-stamina`, `adventure-rewards` (chests, edelweiss, photo quests) and this one.
This plan says **what a place is and whether a player has been there**. Navigation and rewards
consume the catalogue (travel points, chest spots at POIs, photo targets); objectives consumes the
`PoiDiscovered` / `ViewpointSynced` / `Interacted` events.

**Shared contract used here** (from `adventure-objectives`): namespace `UnitSport.Adventure`, code in
`src/Adventure/` (this plan: `src/Adventure/Places/`); `AdventureService` at `World/Adventure`
(server and every client, `Instance?.`), everything gated by `AdventureService.Instance?.Active(peer)`
(off per player in a BR round, `BrManager.Playing`; off on test worlds unless a probe names
`adventure`); sections declared in the owner's file as `SectionKey<T>`, read with
`progress.Get(key)`, marked with `Touch(key)`, synced by the generic `SectionSync`; events raised on
the server only, after validating and writing the section, through `AdventureService.Events.Raise`;
offline the client plays the server's part (peer 1, key `local`). This plan owns the reserved
sections **`places`** and **`fog`**, the reward kind **`"reveal"`**, the **Atlas** tab of
`Ui/AdventureLog`, the free-roam **adventure map** (with the `IMapOverlay` hook navigation draws
into) and the phase-1 **interactable POI markers**.

## Goal

Real Switzerland is full of named places; walking up to one should feel like finding it. Every
summit, pass, castle, lake, waterfall, tower, chapel, station and hut the national survey names
becomes a place the game knows, the map stays clouded until you have been around, climbing to a
summit cross clears the view around it, and every place you reach is a stamp in a passport, the
Swiss Atlas, with a short card of facts. Completion is counted per canton.

Out of scope: a geography quiz ("Wo bin ich?": a screenshot of a spot, guess where on the map) is a
later idea that would reuse the catalogue and the adventure map; points of interest outside
Switzerland (France tiles: no TLM); photos on cards; a shared party Atlas.

## 1. Data pipeline: `PoiStage`

### 1.1 Sources (verified in `SWISSTLM3D_2026_LV95_LN02.gpkg`)

Total **~45 000** nationwide, about 1.1 per km²; Western Valais (the dev region) ~2 500. Chairlifts,
T-bars and transport ropeways are not stations (navigation's rule). TLM has no PostBus operator:
`BusStop` covers every bus stop, and `VillageStop` is the stop nearest the GWR core of each
`places.json` town whose name contains the town's name (else the nearest within 400 m).

### 1.2 Ids: stable across preprocessor runs

A POI id is a string `<tag>:<slug>.<hash>`, e.g. `peak:rigi-kulm.3fa9c01b2e`:
- `<hash>` is 40 bits (10 hex) of SHA-256 over the **source identity**: the TLM `uuid` for every TLM
  row (peak, pass, lake, tower, station...), `cablecar` = line uuid + `/top` or `/bottom`, a
  castle's `osm:<type>/<id>` or `egid:<EGID>` (`CastleStage.Candidate` gains a `SourceId`), a merged
  bridge the uuid of its longest segment. Collisions within a kind are checked at build and fail it.
- `<slug>` is the name, lower case, accents stripped (`PlaceIndex.Normalize`), non-letters to `-`,
  cut at 32. It is **cosmetic**: `PoiCatalogue.Resolve` matches on `<tag>` and `<hash>` only, so a TLM
  rename keeps everyone's progress. Saved progress always holds the canonical string (readable files).
- **Aliases**: the curated cards (1.4) give short names, `peak:rigi-kulm`, `tower:uetliberg`,
  `cablecar:bettmerhorn`; quests, rewards and photo targets may use either form, `Resolve` returns the
  canonical POI. A TLM release that drops a uuid orphans its id: saved stamps stay (counted nowhere),
  and `--poisstats` lists curated aliases that no longer resolve.

### 1.3 The stage

`tools/TerrainPreprocessor/PoiStage.cs`, `PoiStage.Run(tlmPath, outDir, available, gwrPath?,
boundariesGpkg?, osmPbf?)`, following `PlaceStage` / `LandingStage`:
- **Standalone** with `--pois` (needs `--out`, `--tlm`; optional `--gwr` for `VillageStop` and the
  canton fallback, `--boundaries <swissBOUNDARIES3D gpkg>`, `--osm-pbf` for castles), and after every
  `--places` pass when `--tlm` is given. `--pois-file <path>` writes elsewhere, like `--landings-file`.
  `tools/MapCore/Pipeline` gets the step so MapSetup and the in-game downloader build it.
- **Ids are assigned over the whole table, then filtered** to POIs whose tile is in the manifest
  (`available`, as `PlaceStage`): a region build and the nationwide build give the same ids.
- **Canton**: point-in-ring against swissBOUNDARIES3D's `kantonsgebiet` (the ring reading moves from
  `tools/MapSetup/Bake.BakeCantons` into a shared `CantonRings` in the preprocessor, which MapCore
  already references); without it, the canton of the nearest `places.json` town within 5 km
  (`GDEKT`). Codes are the two letters.
- **Elevation**: TLM `hoehe` where present (peaks, passes), else the built `.terr` sampled at the
  point (`TerrainSampler`).
- **Tier** (what counts for completion): **1 Landmark** = has a curated card (~200); **2 Notable** =
  Hauptgipfel, Alpiner Gipfel, Strassenpass, castle, tower, named waterfall, lake >= 10 ha, hut,
  cable-car top, covered bridge, dam (~5 000 nationwide, ~190 a canton); **3 Minor** = the rest
  (hills, hiking passes, chapels, stations, bus stops, landings). Minor POIs are stamped and shown
  but do not count toward completion.
- Console: counts per kind and tier, top names, unresolved aliases (`--poisstats` prints only that).
- Numbers and names go through invariant culture (`general/invariant-culture-floats`).

### 1.4 File format: `pois.bin`

`tools/TerrainFormat/PoiFile.cs` (shared by the preprocessor and the game, like `HorizonFormat`),
written next to the chunks (`terrain_chunks/` is `.gdignore`d), region-wide, not per tile:

- Header `POI1`, version, counts; a **string table** (names, deduplicated); the **canton table**
  (codes, and per canton the region's totals of tier 1/2 POIs and of land fog cells, 7); records;
  lake outlines (int32 decimetre offsets from the first point).
- Record (32 bytes): `hash` (5 B), `kind` (1), `flags` (1: `Viewpoint`, `Cross`, `Top`,
  `VillageStop`, `Named`), `tier` (1), `canton` (1), `discoverRadius` (1, metres / 2), `revealRadius`
  (1, x 100 m), E and N (2 x uint32, decimetres from 2 480 000 / 1 070 000, the `CountryData`
  lattice origin), elevation (int16 m), name index (int32), `lineKey` (int64, cable cars:
  `Ropeway.Key` of the TLM line's bottom end, `world/ski-lifts`; else 0), outline index (int32).
- **Budget**: ~45 000 x 32 B + ~0.9 MB names + ~0.5 MB outlines = **~2.9 MB nationwide**
  (~1.2 MB deflated on the wire), ~65 B per tile on average; Western Valais ~150 KB.

Card text comes in three layers:
1. A **generated line** from the POI's own data: kind, height, canton, nearest town.
2. **Wikidata facts**: the preprocessor matches each POI to a Wikidata item by name, kind and distance
   (< 500 m) and stores a few structured facts (first ascent, year built, length, an image credit) in
   `atlas_facts.json`. Wikidata is CC0, so no attribution is needed. A match below the confidence
   score is dropped, never guessed.
3. **Curated cards** for the ~200 famous landmarks, drafted by Claude from layer 2 and reviewed in a PR.

Curated cards are **not** in the file: `res://assets/adventure/atlas_cards.json` (~200 entries,
English: `{ "alias", "id", "title", "fact" }`), shipped with the game like
`assets/account-server.json`, so a fact can be fixed without rebuilding tiles. A tier-0 test checks
every alias is unique and well formed; `--poisstats` checks they resolve against a built region.

## 2. The catalogue at runtime

`src/Adventure/Places/PoiCatalogue.cs` (plain C# over `PoiFile`, unit-tested), one instance in
`PlacesService` (section 3), on the server and every client:

```csharp
public sealed class Poi {                    // immutable, built once at load
    public string Id; public PoiKind Kind; public PoiFlags Flags; public byte Tier;
    public string Name, Canton;               // Canton = "UR", "" outside
    public double E, N; public float Elevation;
    public float DiscoverRadius, RevealRadius; public long LineKey;
    public string KindTag => ...;             // "peak", "pass", ... (PoiDiscovered.Kind)
}
public static PoiCatalogue Empty, Fixture();  // generated world / fixture probes
public Poi? Resolve(string idOrAlias);        // canonical id, cosmetic slug ignored, curated alias
public void Near(double e, double n, float radiusM, List<Poi> into, PoiKind? kind = null); // no alloc
public ReadOnlySpan<Poi> InTile(TileId t);    // rewards' RewardPlacer input, tile buckets
public IReadOnlyList<Poi> InCanton(string code), OfKind(PoiKind k);
public CantonTotals Totals(string code);      // tier 1/2 POIs, land fog cells (from the file)
public bool InLake(Poi lake, double e, double n, float bufferM);
```

Buckets per 1 km `TileId`; `Near` scans the 3 x 3 tiles around (radii are <= 200 m; lakes by bbox).
**Sync**: `AssetKind.Pois = 17` (`pois.bin`), pulled once during `ClientTerrainSync` with
`SyncFileAsync` like `Landings` and `Ropeways` (`net/region-file-sync`), served by the HTTP mirror
too; `PoisReceived` reloads the catalogue. An older server answers "missing": empty catalogue,
adventure places idle. Offline, the client reads `pois.bin` from its chunk dir
(`TerrainPaths.FindChunkDir`). Generated world: `PoiCatalogue.Empty`.

## 3. Discovery rules (server)

`src/Adventure/Places/PlacesService.cs`, a `Node` at `World/Adventure/Places` (server and every
client, created under `Systems.On(Systems.Adventure)` beside `AdventureService`; offline the local
instance plays the server part). The rules are pure: `DiscoveryRules` (unit-tested).

- **Tick**: 1 Hz on the server inside `ServerStats.Ran("places", ...)`, for each peer with
  `Active(peer)`: read `FootPlayer.NetGlobal` (LV95, `net/positions-on-the-wire`), the ride kind and
  AGL, `PoiCatalogue.Near(at, 200 m)` into a reused list, then `DiscoveryRules.Check`.
- **Radii and conditions** (horizontal; `dz` against the POI elevation):

  | Kind | Radius | Also |
  |---|---|---|
  | Peak, SummitCross, Hut | 40 m (hut 50 m) | `dz` within 25 m; **unmotorised only** (foot, climbing, skis, mount, bike) |
  | Pass | 80 m | `dz` within 30 m; any ground mode |
  | Castle, Dam | 80 m | AGL < 150 m |
  | Lake | inside the outline buffered by 60 m | AGL < 150 m; a boat counts |
  | Waterfall, Church, Chapel, LookoutTower | 50 m | AGL < 150 m |
  | Bridge | 30 m of its midline | any ground mode |
  | RailStation, ShipLanding, CableCarStation | 60 m / 40 m / 60 m (navigation's unlock radii) | AGL < 50 m |
  | BusStop | 30 m | AGL < 20 m |

- **Two consecutive hits** discover (as navigation's unlock): a jump-cut through a radius does not.
- **How you travel (decided)**: discovery and fog count only when the player is **on foot** or flying a
  **light aircraft**.
  - On foot covers walking, running, climbing, swimming, skiing, the paraglider, the wingsuit and the
    pigeon.
  - Light aircraft are small planes, gliders and helicopters.
  - Commercial aircraft (the airliners with cockpits) and every ground vehicle (cars, trucks, buses,
    bikes, boats, trains) reveal nothing: you have to get out.

  The check is one server-side table, `PlacesRules.Reveals(rideKind)`, keyed on the ride kind the
  server already replicates, so changing the rule is a one-line edit. Mounts will count as on foot
  once they exist.
- **Earned by moving**: positions are client-authoritative (`src/Net/CLAUDE.md`), so the server
  flags a **jump** when a 1 s step exceeds what the replicated ride can do (foot/mount 40 m/s, car
  90, aircraft 320). After a jump, nothing within 300 m of the landing point is discovered and no fog
  is revealed until the body has moved 300 m from it by itself. Server-sanctioned moves (navigation's
  travel to an unlocked point, `ChatManager.ForceTeleport` from an accepted invite) call
  `PlacesService.Arrived(peer, e, n)` and are treated the same way: travel lands where you already
  have the stamp. The M place search, `/tp` and admin teleports get no exemption.
- **Not while** in a BR round (`Active` false), dead or knocked out, or seated as a passenger in
  someone else's vehicle that is a train or ropeway cabin **for peaks** (riding the Rigi railway to
  the top stamps the station, not the summit).
- **On discovery**: write the `places` section (`Found[id] = day`, the ride mode), `Touch`, then
  `Events.Raise(new PoiDiscovered(peer, key, poi.Id, poi.KindTag, poi.Canton))`, then the owner RPC
  `Stamped(id)` for the toast, then the milestone check (7.3). Fog is revealed around the POI too
  (`max(300 m, DiscoverRadius)`).
- **Toast** (client, `Places/StampToast`): a banner below the compass strip (navigation owns the
  top-centre strip; this sits under it, clear of the centre): the kind's stamp pressed in with a
  thump (`SfxBank`, synthesised, so in the sound player), "Rigi Kulm · 1 797 m · SZ", 3 s, queued,
  one at a time; minor POIs show a small line instead of a banner, and a burst (a bus ride past ten
  stops) folds into "+4 places". Hidden in a race and while a page holds `UiFocus`.

## 4. Fog of war

- **Cells**: 250 m, on the `CountryData` lattice (`MinE` 2 480 km, `MinN` 1 070 km, 360 x 230 km):
  1 440 x 920 cells, 16 cells (4 x 4) per 1 km tile. The relief under it is 500 m
  (`MapRelief`), so 250 m fog edges read as soft curves after filtering.
- **Reveal**: every server tick, the cells whose centre lies within **300 m** of the body (any mode,
  subject to the jump rule); a viewpoint sync, a discovery or a `"reveal"` reward reveals a disc
  (section 5). Pure `FogMask` (unit-tested): `Reveal(e, n, radius) -> changed tiles`,
  `Revealed(e, n)`, `Count(canton lattice)`.
- **Storage** (`fog` section, `FogProgress { int V; string Mask; }`): the sparse set of tiles with any
  revealed cell, as tile index (`(N - MinN) * 360 + (E - MinE)`) delta-varints + one `ushort` mask
  each, deflated, base64. A player who has roamed 300 km² holds ~1 KB raw (~1.4 KB in JSON); the
  whole country is ~125 KB raw and < 5 KB deflated (masks all `0xFFFF`, deltas 1). In memory a
  `Dictionary<int, ushort>`.
- **Sync**: the generic `SectionSync` would resend the whole mask, so fog has its own RPCs (allowed by
  the contract): `FogFull(byte[] deflated)` once after join, then `FogDelta(int[] tiles, ushort[]
  masks)` at most once a second, only when cells changed. The `fog` section is still `Touch`ed for
  saving (the service saves at most once per 5 s).
- **Drawing** (client): one `Image` of 1 440 x 920 `L8` (1.3 MB, one byte per cell, 255 = fog) and an
  `ImageTexture`, written on `FogFull` and patched per `FogDelta` (`ImageTexture.Update` only then,
  never per frame). The adventure map draws it over the relief with a `ShaderMaterial`: linear
  filtering, a `smoothstep` edge, and per style a cloud look (Cartoon: flat paper clouds with a drawn
  outline; PS1: dithered; Realistic: soft haze), with a slow scroll from `TIME` only on the clouds'
  noise. Discovered POIs show on revealed cells; undiscovered tier 1-2 POIs under revealed cells show
  as a grey "?" of their kind (sighted, not stamped); nothing shows under fog.
- Not on the compass or in the world: fog is a map-only idea.

## 5. Viewpoints and interactable markers

- **Viewpoints** (flag `Viewpoint`): peaks with a summit cross (`Cross`), standalone summit crosses,
  lookout towers, cable-car **top** stations, road passes (Strassenpass). ~1 100 nationwide.
- **Reveal radius** (stored in the file): towers 3 km; passes 3 km; crosses and cable-car tops
  `clamp(2 km + 1.5 km x (elevation - 500 m) / 1 000 m, 2 km, 7 km)` (Pilatus ~5.6 km, the
  Matterhorn 7 km). Phase 2 may replace the disc by a viewshed precomputed in `PoiStage` from the
  coarse grid (rays every 2 degrees on 250 m cells, stored as cell runs), so a viewpoint reveals what
  it can actually see.
- **Markers** (`Places/PoiMarkers`, client): within 1.5 km, a `MultiMesh` per marker kind, one mesh
  built once (`PoiMarkerMeshBuilder`, `[Showcase("Adventure")]`, rule
  `general/no-mesh-rebuild-per-frame`), instances rewritten only when the set in range changes and on
  an origin shift. Kinds: **summit cross** (on `Cross` peaks; the real one is not in swissBUILDINGS3D),
  a **telescope** (Fernrohr) at towers' feet, cable-car tops and passes, and a **stamp post** (a
  yellow hiking-sign post with a stamp box, as the real Swiss Stempelstellen) at tier 1 landmarks. An
  unsynced viewpoint's marker has a dim glint; synced, a small Swiss flag.
- **Interact** (`interact_mount`, within 3 m): client RPC `RequestInteract(string poiId)` ->
  server `PlacesService.ServerInteract(peer, poiId)`: `Active(peer)`, the POI has a marker, the peer's
  `NetGlobal` within 6 m. Then: discover it if new (3), for a viewpoint **sync** (write `places.Synced`,
  reveal its disc in `fog`, `Touch` both, raise `ViewpointSynced(peer, key, id, canton)`), and always
  raise `Interacted(peer, key, id)` (objectives' phase-1 interactables). Reply `Synced(id)`: the client
  plays the "look out" moment: the camera rises and turns slowly once round over 3 s while the
  adventure map's fog clears in a picture-in-picture (skipped in VR: the fog clears on the wrist).
- **Reward handler**: `AdventureService.RegisterReward("reveal", (peer, arg) => ...)`; `arg` is a POI
  id or alias, optionally `@<km>` (`"tower:uetliberg@4"`); default radius the POI's reveal radius or
  2 km. Unknown POI = the catalog test fails (objectives' `QuestCatalogTests`). Note for objectives:
  its example `"ZH:uetliberg"` becomes `"tower:uetliberg"`.

## 6. The adventure map

`src/Adventure/Places/AdventureMap.cs`, a `Screen` on the shell's stack.
- **Built from what exists**: the relief texture of `Ui/MapRelief` (embedded `swiss_relief.gz`, no
  new data) and the pan/zoom/LV95-to-screen math of `Ui/MapCanvas`, extracted into a shared
  `Ui/MapView` (`ToScreen`, `ToLv95`, `Ppm`, pan, zoom, the move tool's input); `MapCanvas` keeps its
  status image and drawing tools on top of it, and its `--mapcheck` must still pass. Canton borders
  as `MapCanvas` draws them (one `DrawMultiline`).
- **Layers**, redrawn only on change: relief; fog (4); POI icons (one atlas texture of kind glyphs,
  decluttered by tier then elevation, labels at zoom); the player's arrow and party members; then
  every `IMapOverlay` registered (`AdventureMap.AddOverlay`): navigation's pins and travel points.
  ```csharp
  public interface IMapOverlay { void Draw(MapView view); bool Click(Vector2 lv95, MouseButton b); }
  ```
  (navigation's proposal, adopted; `lv95` relative to the lattice origin in metres, a `Vector2` is
  precise to well under a metre there.)
- **Selecting a POI** opens its card (7) in a side panel: Track (sets `AdventureService.TrackedTarget`
  to the POI's name, LV95 and radius), Show in Atlas.
- **Where it opens**: `M` / quick menu **Map** / wrist menu Map while the adventure is active for the
  player (the place search, `PlaceSearchUi`, becomes the map's search box; travelling from it follows
  navigation's rules); with the adventure off, M is the place search as today. The phone's Map app
  gets a **Map** button to it. In a BR round M stays `BrMap`.

## 7. The Swiss Atlas

### 7.1 Where

A tab of `Ui/AdventureLog`: `AdventureLog.RegisterTab("atlas", "Atlas", 20, BuildAtlas)` (quests are
the log's first tab; the Journal opens on J). Also reached from the adventure map's card ("Show in
Atlas") and from a **stamp toast** click. Built with `UiKit` / `UiTheme`, follows `ui/ux-guidelines`
(self-review checklist before the PR) and `ui/style-guide`; rebuilt on `SectionChanged("places")`
only, with a shape string, as `ActivitiesScreen` does.

### 7.2 Layout

- **Left**: the six **chapters** and their cantons, each with two bars: **Landmarks** (tier 1+2 found
  / total in this server's map) and **Map** (fog cells revealed / land cells). Chapters are a
  presentation grouping by canton, never overlapping (decided useful: 26 cantons is too long a flat
  list, and a chapter is a natural "complete Ticino" goal):
  Romandie GE VD NE JU FR · Mittelland BE SO AG BL BS ZH · Central Switzerland LU ZG SZ UR OW NW ·
  Eastern Switzerland SH TG SG AR AI GL · Ticino TI · Alps VS GR. (A table in `AtlasChapters.cs`.)
- **Right**: the selected canton's **stamp grid**: tier 1 cards first (a found one shows its stamp;
  an unfound one its kind's outline and, if sighted under revealed fog, its name), then tier 2 by
  kind with counts, then a folded "Minor places" list. A cantonal coat of arms is out of scope; the
  canton header uses its code in a shield.
- **Card** (`AtlasCard`): stamp (kind glyph, name round the rim, the date and the mode, "on foot",
  drawn in `_Draw`, no textures), name, kind, elevation, canton, the fact; Track, Show on map.
  **Curated fact** from `atlas_cards.json`, else a **generated** one (`AtlasFacts.For(poi, catalogue)`,
  pure, unit-tested, English, invariant numbers with a thin space as thousands mark): a peak's rank by
  height in its canton among the catalogue's peaks and the nearest town; a lake's area and altitude; a
  castle's kind (fortress, manor, ruin from `CastleKind`); a cable car's rise and length from its
  line; a station's altitude and the nearest peak; a pass's road and the cantons it joins.

### 7.3 Completion and milestones

- `AtlasProgress` (pure): per canton, found tier 1+2 / `Totals(code)`; per chapter, the sum.
  Counted against **this server's catalogue** (a region server has a part of Switzerland: the bars
  say "of this map"; ids being stable, a later bigger map keeps every stamp).
- **Milestones** at 25, 50, 75 and 100 % of a canton's landmarks: the `places` section keeps the
  highest one reached per canton, so each is raised once:
  `public sealed record CantonMilestone(long Peer, string Key, string Canton, int Percent) : AdventureEvent(Peer, Key);`
  in `PlacesService.cs`. A chapter at 100 % raises `ChapterCompleted(Peer, Key, string Chapter)`.
  Rewards (titles, stamina) are the rewards and objectives plans' to attach.

## 9. Bots

Discovery is a side effect of position, so a bot body stamps places like a player. A bot has no
`PlayerKey`, so it gets the objectives plan's session-only progress (`peer:<id>`, never saved): its
discoveries are written and raised (a bot quest can use them) and vanish when it leaves. The
viewpoint sync has a server path a bot can call, `PlacesService.ServerInteract(peer, poiId)`, and a
bot can read `PoiCatalogue.Near` as a sense ("nearest summit cross"). Rows in `bots/bot-capability-map`:
"discover a place" **done** (position, session-only progress); "sync a viewpoint / stamp post" **gap**: seam `TryInteract`,
server path `ServerInteract`, sense `PoiCatalogue.Near`, no brain uses it (a guide-bot later).

## 10. Network

- **Asset**: `AssetKind.Pois = 17` (`pois.bin`), region file sync (2).
- **Client -> server**: `RequestInteract(string poiId)` (reliable).
- **Server -> owner** (`RpcId`, reliable): `Stamped(string poiId)` (toast; the `places` section follows
  by `SectionSync`), `Synced(string poiId)`, `FogFull(byte[] deflated)`, `FogDelta(int[] tiles,
  ushort[] masks)` (<= 1/s).
- Nothing broadcast: progress is private. Markers and the catalogue are the same on every peer from
  the same file; no replicated property is added.
- **Protocol**: one bump for this plan's RPCs and the new `AssetKind` (`Handshake.Protocol`, from
  whatever objectives and the plans merged before it leave it; `net/protocol-handshake`).

## 11. Persistence

Through objectives' `AdventureBook` (`user://adventure/players/<fingerprint>.json` on the server,
`user://adventure/local.json` offline). Two sections, declared in this plan's files:

```csharp
public static readonly SectionKey<PlacesProgress> Section = new("places", Version: 1, Migrate: null);
public sealed class PlacesProgress {
    public Dictionary<string, Stamp> Found { get; set; } = new();   // canonical PoiId -> stamp
    public HashSet<string> Synced { get; set; } = new();            // viewpoints synced
    public Dictionary<string, int> Milestones { get; set; } = new();// canton -> highest % raised
}
public sealed record Stamp(int Day, byte Mode);                     // days since 2026-01-01, ride mode

public static readonly SectionKey<FogProgress> Fog = new("fog", Version: 1, Migrate: null);
```

Typical `places`: a few hundred stamps, ~15 KB of JSON; worst case (every POI of the country) ~1.8 MB,
acceptable once. Lookups by id go through `Resolve`, so a renamed slug matches the stored stamp.
