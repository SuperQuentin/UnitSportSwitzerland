# Trainer edition: Nakama backend, an edition and platform build tool, then the trainer-only game

## Context

The owner wants a separate product made from the game: home-trainer riding only, with multiplayer races,
events and scoreboards. Decided with the owner on 2026-10-22:
- **Nakama** is the meta backend (accounts, leaderboards, tournaments, clubs, matchmaking), **from the start**.
  The realtime ride stays on the Godot ENet server.
- Nakama runs from a **docker-compose** file. This is the first deliverable.
- A **build tool picks the edition** (full, trainer, server) **and the platforms**. It comes in two forms: a
  script with a menu, and a Godot editor dock on top of that script.
- The trainer game itself builds on `docs/plans/home-trainer-rides.md` (#901).

What exists (explored on 2026-10-22):
- **Networking**: Godot ENet with 32 clients (`src/Net/NetworkManager.cs`). The race server is authoritative
  (`src/World/RaceManager.cs`: checkpoints, `Plausible()`, finish times on `ClockSync`). Each install has an ECDSA
  identity (`src/Net/PlayerKey`). There is no account, database or backend.
- **Saved stats**: `src/BattleRoyale/BrStats` is the only saved scoreboard, a JSON file on one server.
- **Build**:
  - `tools/release.sh` (247 lines) holds `ensure_preset`, `export_preset`, `has_game`, `fetch_tools` and
    `tarball`. It loops over hardcoded presets (Windows Desktop, Linux, macOS, Android).
  - The presets live in the gitignored `export_presets.cfg`, with a CI copy at `tools/ci/export_presets.cfg`.
    Every preset has `custom_features=""`.
  - One feature tag already selects the runtime: `dedicated_server` in `Main.cs`.
  - `Systems.cs` sets which systems run, from the CLI only.
  - `tools/` has a `.gdignore`, so files there are never imported by Godot or exported.
- **Editor plugins**: only `addons/godot_ai`, enabled in `project.godot` under `[editor_plugins]`.
- **Docker**: version 29.3 is installed on the owner's machine. `deploy-linux.sh` does not use Docker yet.

## Deliverable 1: Nakama in docker-compose (`tools/nakama/`)

- **`tools/nakama/docker-compose.yml`**:
  - `postgres`:
    - `postgres:16-alpine`, with the named volume `nakama-db` (no data files in the repo);
    - a healthcheck with `pg_isready`;
    - password from `.env`.
  - `nakama`:
    - `heroiclabs/nakama:<pinned 3.x>`. Use the newest stable tag, at least two weeks old, checked with
      `docker pull` when building it.
    - It waits for `postgres` with `depends_on: condition: service_healthy`.
    - Its entrypoint is `/bin/sh -ecx` with
      `nakama migrate up --database.address $$DB && exec nakama --config /nakama/data/local.yml --database.address $$DB`.
    - Ports: 7349 (gRPC), 7350 (HTTP and realtime API, used by the game) and 7351 (admin console). Bind 7351 to
      `127.0.0.1` only.
    - `./local.yml` and `./modules/` are mounted read-only into `/nakama/data/`.
    - A healthcheck runs `/nakama/nakama healthcheck`.
- **`tools/nakama/local.yml`**: name `unitsport`, `logger.level: INFO`, `session.token_expiry_sec`,
  `socket.server_key`, `runtime.http_key` and `console.username/password`. Secrets are read from env vars that
  compose passes in from `.env`.
- **`tools/nakama/.env.example`** is committed and lists `POSTGRES_PASSWORD`, `NAKAMA_SERVER_KEY`,
  `NAKAMA_HTTP_KEY`, `NAKAMA_CONSOLE_USER/PASSWORD` and `NAKAMA_ENCRYPTION_KEY`. Add **`tools/nakama/.env`** to
  `.gitignore`.
- **`tools/nakama/modules/`** holds a TypeScript runtime module, built to `index.js` with a small
  `package.json` and `tsconfig`:
  - `submit_result`, a server-to-server RPC that takes the `http_key`. The race server posts
    `{course, event, playerKey, timeMs, avgWatts}` to it. A client session calling it is refused.
  - A leaderboard `course:<id>`, created on first use, where a lower time is better.
  - `healthcheck`, an RPC that returns the version.
- **`tools/nakama/up.sh`**:
  - copies `.env.example` to `.env` when `.env` is missing, with random keys generated by `openssl rand`;
  - builds the module;
  - runs `docker compose up -d` and waits for the health check;
  - prints the console URL.
  - It also accepts `down` and `logs`.
- **Linux server**: `tools/deploy-linux.sh --nakama` copies `tools/nakama/` over and runs `docker compose up -d`
  there. The server's `.env` stays on the server and is never overwritten.
- **Note**: `docs/notes/net/nakama.md` covers ports, keys, the trust boundary (only the race server writes
  scores), backup (`pg_dump` of the volume) and upgrades. Add one index line in `src/Net/CLAUDE.md`.
- **Check**: `tools/nakama/check.sh`:
  - brings up compose on throwaway ports through a `-p unitsport-check` project, so it never touches the dev
    stack;
  - calls `healthcheck`;
  - posts a result with the http key, reads it back from the leaderboard, and confirms that a device-auth client
    session calling `submit_result` gets 403;
  - runs `docker compose down -v`.
  - It is not in the quick tier, because it needs Docker.

## Deliverable 2: the build tool, a script plus an editor dock

### 2a. The shared export library: `tools/lib/export.sh`

- Move `ensure_preset`, `export_preset`, `has_game`, `fetch_tools`, `tarball` and the per-platform packaging out
  of `tools/release.sh`. Keep them unchanged, and `release.sh` sources the library.
- Run `release.sh --no-upload` before and after the move and compare the asset lists: the release must not
  change.

### 2b. Editions as data: `tools/editions.cfg`

The file is committed, with one INI section per edition:

```ini
[full]       features=""          platforms="windows,linux,macos,android"  suffix=""          product="UnitSportSwitzerland"
[trainer]    features="trainer"   platforms="windows"                      suffix="-trainer"  product="UnitSport Ride"   exclude_extra="assets/br/*, ..."
[server]     features=""          platforms="linux"                        suffix="-server"   dedicated_server=true
```

- `platforms` lists what each edition supports. The tool refuses an edition and platform pair that is not listed
  there, for example trainer on Android until RideLink works there.
- A preset for an edition and platform is **generated** from the base platform preset in `export_presets.cfg`:
  - name `"<Platform> [<edition>]"`;
  - `custom_features`, `exclude_filter`, the product name and the Android package id set from the edition;
  - `dedicated_server` set for the server edition.
- Presets are written into the build worktree's copy of `export_presets.cfg` only, never the user's file. The
  `full` edition keeps the existing preset names, so CI and `release.sh` behave exactly as before.

### 2c. The script: `tools/build.sh`

- **With no arguments, a numbered menu**:
  1. pick the edition;
  2. toggle the platforms that edition allows;
  3. pick debug or release;
  4. confirm.
- **Flags**: `--edition trainer --platform windows,linux [--debug] [--out DIR] [--list]`.
  - `--list` prints the editions and platforms and whether each export template is installed.
  - With flags, it runs with no prompts, which is what CI and the dock use.
- **Steps**:
  1. a detached worktree of `HEAD` (the `release.sh` pattern), so working files are never touched;
  2. the presets generated for the edition;
  3. `dotnet build`, then `--import`, then `export_preset` for each platform;
  4. packaging through `tools/lib/export.sh`.
- **Output**: `test_output/build/<edition>/UnitSportSwitzerland<suffix>-<sha>-<platform>.<ext>`, with a summary of
  sizes and skipped platforms. It never uploads anything; releasing stays with `release.sh`.
- **Later**: `release.sh` gains `--edition` (default `full`), so a trainer release reuses the same code. The asset
  names carry the suffix, and `src/Core/UpdateInfo.cs` (lines 85 to 93) matches assets by the running edition.

### 2d. The editor dock: `addons/edition_builder/`

- **Files**: `plugin.cfg` and a C# `EditorPlugin` with `[Tool]`. Enable it in `project.godot` under
  `[editor_plugins]`.
- **The dock** holds an edition dropdown and platform checkboxes, both read from `tools/editions.cfg`. A platform
  the edition does not allow is greyed out, and so is one with a missing template, with the reason in a tooltip.
  Below them are a Debug/Release toggle, a **Build** button and a log panel.
- **Build** runs `tools/build.sh --edition … --platform …`:
  - It starts the script with `OS.Execute`. On Windows that goes through Git Bash's `bash.exe`, found from the
    PATH or `C:\Program Files\Git\bin\bash.exe`.
  - It streams the output into the log on a thread, with `CallDeferred` for UI updates.
  - **Open folder** shows `test_output/build/<edition>/`.
- The dock never duplicates the build logic: the script is the single source of truth.
- Add a note, `docs/notes/general/edition-build.md`, with an index line in the root `CLAUDE.md` notes list. Also
  update `local-release.md`.
