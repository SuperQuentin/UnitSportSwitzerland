# Test worlds from the menus (#999)

- **What**: `Core/WorldChoice` lists the worlds a session can play: the UnitSport open world (default) and the test
  worlds the checks run on, the traffic lights region (`tools/signal-test-region`) and the fixture courses
  (`Terrain/Fixture`: junction, straight, hairpin, narrow, verge, airport, lake, parking, garage, site, flat). Ids are
  short (`open`, `signals`, `junction`...): they go in the settings, on the server's command line and on the wire.
- **Where**: Play solo's Explore card and the Host dialog (`Ui/WorldPicker`, an `OptionButton` with a "Test worlds"
  heading and a line about the pick; items carry their index in `WorldChoice.All` as id). Remembered as
  `GameSettings.SoloWorld` / `HostWorld`. A test world skips the landing map and starts at `WorldChoice.Start`
  (fixtures: the default spawn they are built round; the region: J1's south-west corner); the Host dialog hides
  "Where players start" for one. No new action: the dropdown is reached by keyboard, pad and VR pointer like any option row.
- **How a world applies**: `WorldChoice.Active` is set as a world boots (`ClientWorld._Ready` from `Launch.World`,
  `ServerWorld._Ready` from `--test-world <id>`) and cleared by `WorldStatics.Reset`. While set,
  `TerrainPaths.ParseChunkDirArg`/`FindChunkDir` answer its chunks (`fixture:<course>` or the region's folder),
  `Systems.FixtureCourse` its course, and `Systems.On(Generated)` is false. Null is the open world: every reader
  behaves as before, so command-line runs with `--chunks fixture:x` (all the checks) are unchanged.
- **The traffic lights region in any build**: RoadGen is linked into the game through MapCore, so `WorldChoice.Prepare`
  runs `SignalTestRegion.Run` into `user://worlds/signals/chunks` (raw input in `chunks_temp`). Stamped with RoadGen's
  module id (`built_by.txt`): built again only when RoadGen changed. ~15 s in a release build, **~50 s in the editor's
  debug build**; the loading screen says so (`PreparingDetail`). Hosting builds it before starting the server, so the
  server's 90 s start never goes on it (`GameShell.PrepareThenHost`, a call counter so a build finishing after a
  cancel starts nothing).
- **Saves per test world**: `WorldChoice.SavePath` maps `user://x` (or its globalized form) to `user://worlds/<id>/x`
  while a test world runs. Used by the world-located stores: placed objects and photos, structures, loot, shops, farm
  fields/sales/stands, sleepers, occasion claims, containers. Player-level files (inventory, bank, identity, settings,
  birds, fish) stay shared. A new world-located store must go through `SavePath` too, or a course built at Riddes'
  coordinates puts its things in Riddes.
- **Online**: the hosted server runs with `--test-world <id>` (`HostedServer.Start`). Its status reply's `World` is the
  id (else `real`/`generated` as before): `ServerRow` shows the title and joins with it. `World/Arrival`'s `Rules`
  carries the server's world (protocol 45): a client that loaded another one (typed address, no status reply) fails
  with `ClientWorld.ServerPlays` set and the shell joins again in that world behind the loading screen (`_rejoin`). Only
  the active ids are compared, so CLI checks that pass the same fixture flags to both sides still match ("open").
- **Command line**: `--test-world <id>` on a client (`WorldLaunch.FromArgs`, starts at its start unless `--at`) or a
  server does what the menus do, saves included.
- **Bots**: a session option, nothing a player does: no bot seam.
- **Checks**: `--worldpickcheck --world fixture` (quick: Play solo's picker through the page, then the region built and
  played; restores `SoloWorld`), `tools/worldpicknetcheck.sh` (net: the picker, hosting the junction course and its
  status, joining a `--test-world junction` server from the open world and the rejoin; `nosignals`).
