# Android emulator: running the game and reading its crashes (#1010)

How the v0.79–v0.80 phone crashes were found without a phone (Windows, Oct 2026). Background: `core/platform`.

## Two Android-only crashes (#1010)

- **No `[ModuleInitializer]` may touch a Godot type, directly or through a static field.** Android's runtime (mono) runs module initializers as the game assembly loads, before GodotSharp has its native function pointers. `ConcertRig.UseGodotImages` was one: it ran `ConcertRig`'s static constructor, and its `static readonly StringName` called a null pointer. The game died at the splash screen. Desktop CoreCLR runs them later, so only Android showed it. Register such hooks from `Main._Ready`.
- **A looped `AudioStreamWav` ends inside its buffer.** Godot 4.7 mixes a forward loop up to `LoopEnd` **inclusive** (`audio_stream_wav.cpp`: `end_limit = loop_end`), and `set_data` keeps no padding. `LoopEnd` = the frame count reads one frame past the end on every pass. On desktop that read lands in other heap memory and goes unnoticed. On Android, scudo ends a large block (the 1.4 MB wind) flush against a guard page, so it is a SIGSEGV a few seconds after a solo world opens, at the wind's first wrap. Build loops with `Dsp.LoopWav`: one extra frame, a copy of the first, and `LoopEnd` = the frame count. `--sounds,check` fails a loop that ends past its last frame (`audio/sound-player`).

## Setting up (no Android Studio)

- **Hypervisor:** the emulator needs WHPX ("Windows Hypervisor Platform" feature + `bcdedit /set hypervisorlaunchtype auto`, a reboot) or the Android Emulator Hypervisor Driver. `emulator -accel-check` says which.
- **Pieces, straight from `dl.google.com/android/repository` (no sdkmanager, so no JDK needed for them):** `platform-tools-latest-windows.zip`, `emulator-windows_x64-<build>.zip` and `sys-img/google_apis/x86_64-34_r14.zip`, unzipped into `%LOCALAPPDATA%/Android/Sdk` (`emulator/`, `platform-tools/`, `system-images/android-34/google_apis/x86_64/`). The file names are in `repository2-3.xml` and `sys-img/google_apis/sys-img2-3.xml`.
- **AVD by hand:** `%USERPROFILE%/.android/avd/<name>.ini` (`path=`, `target=android-34`) and `<name>.avd/config.ini` (`image.sysdir.1=system-images\android-34\google_apis\x86_64\`, `abi.type=x86_64`, `hw.ramSize=6144`, 1080×2220, `hw.gpu.mode=host`).
- **Boot:** `emulator -avd <name> -no-snapshot -no-boot-anim -gpu host -no-audio`. Then `adb wait-for-device` and poll `getprop sys.boot_completed`.

## An x86_64 test APK

- **Needs:** the 4.7.2 **mono** export templates (`Godot_v4.7.2-stable_mono_export_templates.tpz` from the godotengine/godot release, unzipped to `%APPDATA%/Godot/export_templates/4.7.2.stable.mono`), build-tools (`build-tools_r35.0.1_windows.zip` → `Sdk/build-tools/35.0.1`, for apksigner), and a JDK 17 (Temurin zip) as the editor setting `export/android/java_sdk_path`.
- **Build:** from a worktree, copy the per-machine `export_presets.cfg` and add the "Android" preset as `tools/release.sh` writes it, with `architectures/x86_64=true`. Sign with a throwaway keystore: `keytool -genkeypair`, then `GODOT_ANDROID_KEYSTORE_RELEASE_PATH/_USER/_PASSWORD`. Run `dotnet build -c Release`, then `--headless --export-release "Android" <apk>`. A different key from the release means `adb uninstall ch.unitsport.switzerland` first.

## Driving it

- **Root:** the `google_apis` image is userdebug, so `adb root` works. In Git Bash set `MSYS_NO_PATHCONV=1`, or `/data/...` paths turn into `C:/Program Files/Git/data/...`.
- **Arguments:** the launcher activity drops intent extras. As root, start the non-exported activity: `adb shell am start -n ch.unitsport.switzerland/com.godot.game.GodotApp --esa command_line_params "--verbose,--rendering-driver,opengl3,--rendering-method,gl_compatibility"` (comma-separated).
- **Taps:** `adb shell input tap X Y` in screen pixels (2220×1080 landscape). `adb exec-out screencap -p > shot.png` to see the screen. Solo: Play solo (264, 425), Start exploring (720, 585), Start here (1942, 951).

## Reading a crash

- **stderr into logcat:** `adb shell setprop wrap.ch.unitsport.switzerland logwrapper` (userdebug only). The next launch prints mono's "Native Crash Reporting" block, with the managed stack when there is one, under the `app_process64` tag. `setprop wrap.ch.unitsport.switzerland ""` turns it off.
- **The signature:** `ERROR: BUG: Unreferenced static string to 0` lines, then `FORTIFY: pthread_mutex_lock called on a destroyed mutex` on `VkThread`. That is the process calling `exit()` after a fatal signal while the render thread still runs. It is not the cause.
- **A native fault** (no managed stack): save `/proc/<pid>/maps` every second as root while it runs. Find the mapping that holds the "native instruction pointer", then disassemble that offset of `lib/x86_64/libgodot_android.so` from the APK (Python `pyelftools` + `capstone`). The library is stripped, so match the instructions against Godot's source for the tag (`gh api repos/godotengine/godot/contents/<path>?ref=4.7.2-stable`). For #1010 it was `AudioStreamPlaybackWAV::decode_samples<int16_t, stereo>`.
- **Which game object:** a throwaway node that logs what started playing (or whatever the fault points at) every 0.25 s narrows it to one stream. The last line before the fault names it.
