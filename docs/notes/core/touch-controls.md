# Touch controls: the phone's on-screen pad (#63)

- **What it is:** `Core/TouchControls` is a CanvasLayer (layer 13) that `ClientWorld` adds next to the prompt bar when `TouchControls.Wanted` (`Platform.IsMobile`, not headless). It is a **virtual gamepad** on device id 8 (`XrPad` is 7). Every action in every mode already has a pad binding (`PlayerInput.RegisterActions`), so the overlay only plays the pad's controls. No action is bound to touch on its own.
- **Layout (canvas pixels, laid out on resize):**
  - floating left stick: any touch in the lower left 42 % × 70 %, 70 px radius, giving LeftX/LeftY;
  - A/B/X/Y diamond at the bottom right;
  - RT/LT left of the diamond (throttle and brake, fly up and down), RB/LB above it;
  - L3 (sprint, fly boost) and R3 (camera);
  - d-pad at the top left (↓ = Walk/Fly toggle, lights, horn, engine, wheels);
  - Start (II) and Back (Bag) at the top right.
- **Labels:** every 0.25 s each button takes the text of the first prompt (`ClientWorld.Prompts`, the prompt bar's source) whose action is bound to that pad button. A button with no prompt is drawn dim. While the overlay is up the prompt bar is empty, because the buttons carry the labels.
- **Look:** any other touch is a look drag. It sends `InputEventMouseMotion { Device = TouchControls.Device }` scaled by `GameSettings.TouchLookSpeed` (Settings → Controls, mobile only, default 1.5×), so the camera turns 1:1 with the finger, as with a mouse. Camera code tests motion with `PlayerInput.IsLookMotion`: the captured mouse or the overlay's drag, **never** the mouse Godot emulates from a touch (`InputEvent.DeviceIdEmulation`), which would turn the camera twice.
- **When it shows:** while the pointer is held (`Input.MouseMode != Visible`: no menu open) and no text field has focus. A real pad's button or a push past 0.5 hides it until the screen is touched again. Hiding it releases every held key. Touches and emulated mouse events count as the pad for `LastDevice`, so the prompts name pad buttons.
- **Haptics:** a light tick on each press, and `PlayerInput.Rumble` on the phone's own motor (`Input.VibrateHandheld`, so the APK needs the VIBRATE permission).
- **Desktop `--mobile`:**
  - The overlay shows, and the mouse plays the finger (`Input.EmulateTouchFromMouse`).
  - `MouseCapture` confines the pointer instead of capturing it, so the mouse stays usable.
  - The menus run at `GameShell.MobileUiScale` (1.15).
  - `--mobile` is whitelisted for the title, so `--mobile --uishot out.png 4` pictures the phone menus.
- **Check:** `--touchcheck --mobile --world fixture`.
  - It taps Walk (d-pad ↓), pushes the stick up for 2 s (≥ 1.5 m walked), drags 240 px (≥ 10° turned) and taps A (≥ 0.3 m risen).
  - It sends touches in window pixels through `Viewport.GetFinalTransform`, as a phone does.
  - Measured: 3.6 m, 45.4° (exactly 240 px × 1.5 × 0.0022 rad), 0.93 m: windowed at 2220×1080 and headless (quick tier, `tools/lib/checkmap.txt`).
  - It runs headless too: the overlay is built under `--touchcheck` there, and counts as in game.
- **The look drag goes out in window pixels** (`GetFinalTransform().BasisXform`). Godot scales a parsed mouse event from window to canvas, as it does the touch. Sent in canvas pixels, it was divided by the UI scale: half speed on a phone, and 5,634 px for a 240 px drag headless.
- **Menus on a phone:**
  - `GameShell.MobileUiScale = 1.15` sizes up every menu. 1.3 overflowed: the Multiplayer card was cut off and Quit hit the title footer.
  - Hidden on a phone: the title's keyboard footer, and the Window / Window size rows.
