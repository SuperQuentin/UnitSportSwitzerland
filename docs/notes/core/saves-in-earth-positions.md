# Saves keep Earth positions and true-north headings

Since #1503 (G2 A2b of `docs/plans/global-tiling-g2.md`). Before it the saves held LV95 metres and grid-north yaws.

- **A place** in a JSON save is `{"x": …, "y": …, "z": …}`, ECEF metres (WGS84), under `"at"`: `GlobalPosJson`, put on
  the `GlobalPos` type, so any saved record with a `GlobalPos` property writes it so. It goes through
  `GlobalPos.ToWire` / `FromWire` (back to the place within 0.1 mm), and does not change when A1 puts ECEF inside.
- **A heading** is `"yawTrue"`, radians from true north at the place (Godot's sense); **a rotation** `"turn"`, the
  quaternion in the local east-up-south there; a place on the ground (a pin, a landing, a spawn, a bay) at altitude 0.
- **In memory** the records keep `GlobalPos` (LV95 inside until A1) and their grid yaws: they convert at the file,
  `at.TrueYaw(yaw)` out, `at.OffsetYaw(t)` in. A record whose file moved holds or gives a `GlobalPos`
  (`Sleeper.At`, `PlacedObject.At`, `Structure.At`, `Pin.At`, `PortableFlag.At`); its `E`/`N` are views for the map.
- **Every store has a version** (`"version": 2`, `EarthSaves.Current`; the adventure sections their own `v`); a file
  without one is the old form, **converted in place on first load and written back, no backup** (the plan's
  decision). The old fields are read by the migration only. Idempotent: a version 2 file goes through untouched.
- Shared shapes and the migrations of the stores read by a Godot node: `src/Core/SavedPlace.cs`,
  `src/Core/EarthSaves.cs` (plain C#, linked into the unit tests, `EarthSavesTests`).

## Not here

- **Keyed by LV95 tiles** (farm fields `{E}_{N}.json`, loot, shops, Christmas claims, chest ids, the container file
  names and `ContainerRecord.E/N`, which say which tile's file a record is in): re-keyed by cube leaf at G2 D, with the
  content generated per tile. The adventure's **fog** (`FogProgress`) is an LV95 250 m lattice of cells, re-keyed there too.
- A Record / Stop session's spool (`SessionSpool`) is a temp file of one run, read back and deleted at Stop: in memory form.
- Interior plans (`user://interiors`) are in the building's own frame.

## Traps

- A record's place goes LV95 → ECEF → LV95 on every save and load: within 0.1 mm, but not bit for bit, so a file saved
  twice may differ in the last digit of an ECEF coordinate (`EarthSavesTests` checks it does not creep over 200 cycles).
  Compare places with a tolerance, never a file's bytes.
- The adventure sections' JSON is also what `SectionSync` sends: their shape is on the wire (protocol 94).
- A movie camera on a rig (`CameraTrack.Relative`) keys offsets in the actor's frame: not a place, never converted.
- A new save that holds a place: a `GlobalPos` property (it saves as `{x, y, z}`), headings `yawTrue`, a `version`.
