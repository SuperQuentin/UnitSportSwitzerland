# Tree LOD: 3D trees near, ray-traced billboards far

Forest tiles hold up to 60k trees, and trees were most of the frame after terrain. Beyond
`StyleKit.TreeNear` (220 m) each tree is a 2-triangle billboard instead of the 20-triangle mesh,
in every style (`ps1_tree` near, `ps1_treefar` far, one body in `shaders/body/tree.gdshaderinc`).
Riddes viewpoints, M1 Pro: 33–36M primitives a frame on `main`, 25–30M with billboards.

- **Same instances, two MultiMeshes.** `ChunkNode.BuildTreeMeshes` makes a far pair from the
  same instance buffers when `StyleKit.TreeFarMaterial` is set (`ClientWorld`, before the first
  tile builds). The near shader collapses a tree beyond the range (`VERTEX = 0`), the billboard
  collapses inside it, and a 40 m band crossfades them per tree.
- **The billboard ray-traces the tree.** A camera-facing sprite of a cone shrinks to a sliver
  seen from above, and from a plane or the valley sides the forest floor showed through. So the
  quad faces the rendering camera, sized to the tree's outline from that elevation (2r across,
  h cos e + 2r sin e up), and each pixel intersects its view ray with the unit mesh: both crowns
  are convex 10-face bipyramids and the trunk a 5-sided prism, so it is 17 plane tests
  (`hit_crown`, `hit_trunk`). The silhouette and the flat facet normals match `ConeMesh` and
  `CrownMesh` from any angle. **Change those meshes and the billboard's constants together.**
- **The crossfade must be complementary.** The 3D tree keeps the pixels where
  `1 - s >= bayer`; the billboard must keep exactly the others (`s > 1 - bayer`). With the same
  test on both, a pixel at `s = 0.5` and `bayer > 0.5` drew neither, and a band of bare ground
  showed under a camera ~230 m above a forest.
- **The tile cut uses the tile's own bounds, height included.** A tile's near MultiMeshes get
  `VisibilityRangeEnd = TreeNear + fade + half-diagonal of the AABB`, so a tile with no tree in
  range draws no 3D trees at all (the shader collapse alone still runs every vertex). Godot
  measures the range to the AABB's **centre**, and a mountain tile's bounds run from the valley
  floor to the summit: a fixed 720 m half-diagonal hid the 3D trees right under a valley camera
  while their billboards had already collapsed.
- **`world_cam_pos`** (a global, `Styles/CameraGlobal`) is the player's camera, set on
  `RenderingServer.FramePreDraw` so it is never a frame stale (a floating-origin shift would flip
  near trees to billboards for one frame). The LOD distance uses it rather than
  `CAMERA_POSITION_WORLD`, so a cockpit mirror or the zoom bubble agrees on which trees are 3D;
  the billboard's orientation and rays use the rendering camera, which is what it is drawn for.
- `--tree-lod off` restores every tree as 3D (pixel-identical to before, the check for changes
  here); `--tree-near m` moves the handover.
- **Heavier trees (Cartoon, `MeshDetail.High`) are culled per tree on the CPU: `NearTrees`.** A
  tile then builds only its billboards and hands its instance buffers over (`TreeMeshes.Near`,
  registered when the trees commit, dropped on release). One MultiMesh per kind holds the trees
  within `StyleKit.TreeReach` (range plus crossfade) of the camera, refilled when the camera
  moves 4 m **or a tile's trees come or go**: a camera standing still while tiles commit
  otherwise never got its near trees. It is a child of the terrain container, so the floating
  origin moves it with the tiles; instances are placed relative to it, refilled on a shift.
  The same tree shader's LOD fade crossfades them against the billboards.
- **Cartoon's billboards trace Cartoon's shapes** (`hit_tier`: 7-sided pyramids, their dented
  underside traced flat; `hit_puff`: ellipsoids, the low-poly puffs traced smooth;
  `hit_trunk6`). Far billboards cast no shadow: traced from the rendering camera, a shadow pass
  would trace them from the light.
