# View-cone priority: what is on screen loads first

- **The load queue is ordered by `ring distance × view weight`** (`ChunkManager.SortByView`).
  `ClientWorld._Process` calls `ChunkManager.SetView(camera)` every frame with the live camera:
  its position, its forward vector, and its *horizontal* half-FOV (`Camera3D.Fov` is vertical
  under `KeepAspect.Height`, so it is widened by the viewport aspect: 75° vertical at 16:9 is
  ~±53°).
- **Weight**: 1 while any part of the tile is inside the cone (half-FOV + 15° margin; the angle
  is taken to the tile's nearest edge, `asin(0.707 / r)` off its centre), climbing linearly to
  `ViewBehindWeight` (4) over `ViewRampDeg` (60°) past the edge. So a tile 4 rings straight
  behind waits for ring 16 in front; the sides wait less. The inner `ViewExemptRings` (2) are
  never weighted: ground underfoot and collision must not depend on where a third-person
  camera points. Ties break nearest-first by Euclidean distance.
- **Angle from the camera, not `_anchors[0]`**, against the *flattened* forward. Looking within
  ~78° of straight down/up (horizontal part < 0.2) there is no preference.
- **Cheap re-sort**: the ring scan + unload pass (`RecomputeDesired`) only reruns on an anchor tile,
  ring table, world-version or `BuildMeshes` change. The view is rounded to a `ViewCone` record
  (camera tile, one of 16 heading sectors, half-FOV to 5°), and only a change of that re-sorts:
  0.16-0.21 ms for 961 tiles (15 rings), so ~1.5 ms at 40 rings. The 15° margin covers the
  11.25° worst-case sector rounding.
- **Measured** (2026-10-01, loopback server + client, empty `--chunks`/`--cache`, 15 rings,
  `--perflog 40`, 961 tiles mostly generated fill): time until every on-screen tile at ring ≥ 3
  was built went 17.9 → 12.5 s and 19.3 → 15.1 s (two pairs of runs; p50 15.0 → 10.5 s and
  16.6 → 13.2 s). Tiles behind finished at about the same time as before (18.8 → 16.6 s, 20.1 → 19.3 s), so
  the total load is not slower. `--fly 0,900,0,30,150,20`: same hitch count as `main` (1-5 frames over 33 ms
  either way). Analysis: `builds.csv` has tile, ring and completion time per build; classify
  each tile by angle from the camera tile.
- Server: no camera, `ViewDirection` stays zero, so pure nearest-first.
