# Generated roads through RoadGen (#559)

- **Why generated tiles had bare roads**: every road layer past the centreline (junction
  polygons, paint, Wartelinie, 3.02/3.03 signs, ATTR yield bits, bike paths, turn lanes, lights)
  is planned offline by RoadGen's network stage (`TileRewriter.Run`) on real tiles.
  `ProceduralWorld.BuildRoads` emits plain segments only (class, paved, default width), and the
  runtime builders draw what the tile carries.
- **Spike** (`tools/GeneratedRoadsSpike`, no Godot): generates a block round the biggest villages
  near the anchor, writes it as the preprocessor's temp output (raw roads + `.keys`, full grids,
  buildings), runs `TileRewriter.Run` once over the block (reference) and once per tile with halo 1
  (what a runtime source would do), and compares the `.road` bytes.
  `dotnet run --project tools/GeneratedRoadsSpike -c Release -- --out test_output/roadgen_spike --villages 8 --size 8`;
  `--no-keys`, `--halo N`, `--no-smooth`, `--dump` (segments of a differing tile).
- **Seams need line keys**: without `.keys`, 30 of 35 tiles differed, the same with `--no-smooth`
  or halo 2. Cause: `BikePlanner.StrokeLayouts` hashes a street's path layout (Track vs TrackMid,
  buffer) from the smallest key on its chain, and a keyless link falls back to its first point,
  which depends on how much of the street the context loaded. `ProceduralWorld.BuildRoadsKeyed`
  gives every segment a `RoadKey`: `gen-line-<l>` / `gen-village-<id>-<k>` plus the metre along the
  drawn line (`DrawnStation`, also the paint stations' origin). With keys: **180 of 180 tiles
  byte-identical** (8 villages, 8x8 blocks), also with halo 2.
- **Cost**: ~200 ms a tile through the file-based `Run`; reading inputs is ~7 ms of it. Almost
  all of the rest is `UrbanField` (2 m wall lattice and +-150 m box filter per tile, lazy, so it
  shows under `RoadHeights.Apply`) rebuilt for all 9 context tiles on every call. With `Facades`,
  `UrbanField` and the grids shared across calls (a measuring hack, not committed): **~46 ms a
  tile** (39-69 per village), results unchanged. The field depends on position and walls only,
  so one cache per world is safe.
- **What it adds on today's network** (3 villages, 35 tiles): 17 junction polygons, 16 yield
  signs + Wartelinie, 28 main-road signs, bike paths and symbols, 14 turn-lane approaches,
  centre and edge lines; **0 lights**: every generated junction is a T (village side streets,
  tributary links) and `PriorityPlanner.InferSignal` wants 4+ arms of two priority roads in a
  dense core. Lights need the generator to grow towns with crossroads.
- **Open for the real change**: split `Run` into a loader and an in-memory core (tiles, grids,
  buildings in); where neighbour grids come from at runtime (full grids cost ~19 ms each to
  generate: cache, or let the stage read `ProceduralWorld.Height`); generated roads meeting a real
  tile's already rewritten roads at a blend seam; whether the server needs the same output for
  traffic priority.
