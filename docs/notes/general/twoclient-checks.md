# Two-client checks: `tools/lib/twoclient.sh`

## Rule

- A `tools/<x>check.sh` that starts a dedicated server and clients sources
  `. "$(dirname "$0")/lib/twoclient.sh" <x>` first thing, and starts every Godot through it:
  `tc_server <timeout> <wait_listening> <log> --server ...`, `tc_client <timeout> <log> [--windowed] ...`
  (add `&` for a background one), `tc_godot` for anything else, `tc_stop` to end a server,
  `tc_ok <n> <logs>` to count `RESULT: ok` lines.
- Never `timeout godot ...`, `kill $SERVER`, `kill %1`, `pkill`, or a hard-coded `godot`: on Git Bash
  a kill stops only the `timeout` wrapper and the server keeps the port until its timeout; the
  winget `godot` link hangs. The lib kills by PID tree (`guard.sh`) and finds the console exe.
- Ports stay per script and passed in (`PORT=...`); keep them distinct from the other checks.
- The script's own RAM watchdog (`guard_watch $$`) sends the script a TERM, then kills its
  children: it prints `[<x>] RESULT: FAILED (stopped by a TERM ...)` and exits 143. Before #795 it
  killed the script outright, which exited 0 with no RESULT line, and `tools/test.sh` read that as
  PASS. The TERM goes first because bash holds a trapped signal until its foreground child ends,
  and killing the child first let the script print its own `RESULT: ok`.
- Clients are headless unless the script says `--windowed` (a speaker, drawn parked vehicles,
  screenshots) or `WINDOWED=1` is set.
- `user://` (loot, bank, placed, birds, CDs, identity) is a fresh `test_output/userdata_<x>` per run
  (Windows `APPDATA`, Linux `XDG_DATA_HOME`, macOS `HOME` of the Godot runs, see below): a check
  never touches real saves. `USERDATA=<dir>` keeps one across runs, `USERDATA=real` uses the real one.
  Every one but the real one gets `test_window.cfg` (`guard_quiet_godot`, #1378): a windowed client
  never takes focus and is silent (`general/testing`).
- The server and every client of a check share that one dir, so they share one `identity.key`: the
  second client logs on the server as `identity XXXX already connected, no sleeper for it`. A client
  that must be a player of its own runs under `( tc_userdata "$OUT/userdata_<x>_B"; tc_client ... ) &`
  (`tools/sleepercheck.sh`, `tools/yardlootnetcheck.sh`); never set `APPDATA`/`XDG_DATA_HOME` by hand.
- **A check of the generated world passes `"${NOTERRAIN[@]}"`** (`--chunks test_output/no_terrain`,
  an empty folder the lib makes) to its server and every client, besides `--generated-world`.
  `--generated-world` alone only lets a server start with no terrain: where `terrain_location.json`
  points at real tiles (the main checkout's D:, 825 tiles), server and clients load them, and the
  generated site office at 2586561,1115543 is real ground there: `siteofficenetcheck` failed "no site
  office door near the spot" (#943). Done for every script whose `AT` is a generated-world place:
  `siteofficenetcheck`, `siteuppernetcheck`, `cranenetcheck`, `sitemachinenetcheck`,
  `sitepalletnetcheck`, `yardlootnetcheck`, `brsquadcheck` (generated Zürich) and `liftsynccheck`
  (unless `CHUNKS=` asks for real data). The default-spawn scripts whose assertions no ground takes
  part in boot the flat test world instead since #992 (pvp, plant, placed, gunshot, useanim, bonk,
  gadgetnet, buildnet, switch, radio; `REAL=1` boots their old ground, `general/check-waits`). Not done:
  the other scripts at the default spawn (2583250,1113250: birds, pigeon, bots, br...), some of which
  take real terrain on purpose (`SERVER_ARGS=`, `REAL=1`, `CHUNKS=`), and those that look for the nearest generated works or shop from the spawn
  with no `AT` of their own (`baycheck`, `palletnetcheck`, `shopcheck`): from the main checkout they
  meet the real buildings round Riddes instead. Give one `NOTERRAIN` if it must see generated ground.

## macOS

> [!NOTE]
> This section was generated by Claude.

Godot on macOS reads neither `APPDATA` nor `XDG_DATA_HOME`: `user://` is
`$HOME/Library/Application Support/Godot/app_userdata/UnitSportSwitzerland` (`OS.get_data_dir()` is
`$HOME/Library/Application Support`, the cache `$HOME/Library/Caches`; checked on 4.7.1). Godot has no
command-line user-dir flag, and `application/config/use_custom_user_dir` is project-wide (it would move
every player's saves), so the lib sets `HOME` instead, for the Godot processes only (`_tc_env`, an
`env HOME=<dir>` prefix in `tc_server`/`tc_client`/`tc_godot`), never exported: git, gh and dotnet in
the script keep the real one. The data lands one level deeper than on Linux,
`test_output/userdata_<x>/Library/Application Support/Godot/app_userdata/UnitSportSwitzerland/`; a
`find "$OUT/userdata_<x>" -path "*farm/*.json"` still finds it. Before #828 every check on macOS used
the developer's real `user://` (`[cd] ... /Users/<me>/Library/...` in the server log) and both clients
the developer's real identity key. A windowed client starts with a cold shader cache under the fresh
`HOME`.

## Why

#221 investigation 3, cluster 20: 18 scripts each re-implemented "start server, wait for
`server listening`, start A and B, grep RESULT" with different kill code (four of them leaked the
server on Git Bash), five ignored `GODOT`, and the loot/bank/placed/birds scripts wrote the real
user data. Before/after runs: see PR (each script fails or passes the same way as on main).

## Same logic, preserved

- Each script keeps its flags, ports, timeouts (now `guard_run` timeouts), log names, RESULT text and
  exit code; windowed clients stay windowed.
- `sleep 12` / `sleep 6` before the clients became "wait for `server listening`" (at most 120 s).
- The lib takes the heavy-run lock (`guard_lock`) unless `GUARD_LOCK_HELD` is set (as under
  `tools/test.sh`), waits for 4 GB free RAM, and the `guard_watch $$` watchdog stays.
- Trap: a check that needs state from an earlier run (an emptied loot epoch, a cracked safe) now
  starts clean every time; pass `USERDATA=<dir>` to reproduce an old state.
- Since sleepers (#644) the real `user://` breaks a check outright: both clients share one
  `identity.key`, the server keeps the last run's sleeper, and whichever client proves first wakes
  at the old spot, off the course (`[sleepers] <name> wakes at` in the server log). That made
  `boatnetcheck` pass every other run and `steamernetcheck` fail on `main` until #792 migrated them;
  `campfirecheck`, `gadgetnetcheck` and `swimnetcheck` failed the same way in a row until #795.

## Migrating old code / open branches

- A branch that adds or edits a `tools/*check.sh`: replace the `guard.sh` source line, `cd`,
  `OUT=`, `mkdir`, `CH=()/CHUNKARG=()` and `stop()` boilerplate by the source line above; replace
  `timeout N "$GODOT" --headless --path . -- --server ... > log 2>&1 &` + the wait loop by
  `tc_server N <wait> log --server ...`, each client by `tc_client`, `kill`/`stop $SERVER` by `tc_stop`.
- Background clients the script leaves running (`tc_client ... &`) are not the lib's to kill:
  keep their PIDs and kill them in your own EXIT trap, which ends by calling `_tc_cleanup`
  (`tools/racecheck.sh`: up to four `--raceauto` clients, each with its own `--cache`).
- Not converted yet: `tools/buildnetcheck.sh` (#281, open). `tools/test.sh` keeps its own Godot
  finder (#269 edits it).

## How to check

`bash tools/<x>check.sh` (with `CHUNKS=` for the real-map ones) and read its RESULT line; after it,
no Godot may hold the script's UDP port (`netstat -ano -p UDP | grep :<port>`).
