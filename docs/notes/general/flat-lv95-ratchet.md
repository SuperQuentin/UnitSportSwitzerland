# Flat-LV95 ratchet: what the global tiling has to remove may only shrink (#1443)

- The world is moving from one flat LV95 plane to tiles in true Earth positions
  (`docs/plans/global-tiling.md`). While the seams of phase G0 are built, `FlatLv95RatchetTests`
  counts, over `src/` (comments and strings left out), the code that treats LV95 as metres on a
  plane, and fails if a count goes **up**:
  - **hand-written LV95 distances** (`de * de + dn * dn`): use `GlobalPos.HorizontalDistanceTo` /
    `DistanceTo` / `HorizontalDistanceSquaredTo`, or for places held as raw doubles the static
    `GlobalPos.HorizontalDistance(e1, n1, e2, n2)` / `HorizontalDistanceSquared` (the instance ones are Earth
    distances since A1, #1502; the static raw-double ones stay the grid's, for LV95 sources). G0b moved 49 of 61;
    the 12 left are not distances between two LV95 places (grid offsets, velocities, km tile rings,
    directions, float maths, the point-to-lake-box test) or sit in `ProceduralWorld*.cs`, which the
    Godot-free `tools/BlendCheck` and `tools/GeneratedRoadsSpike` link without `GlobalPos`;
  - **`SwissProjection` in the game** (0): latitude and longitude go through
    `SwissGeodesy.ToLv95` / `ToLatLon` (`core/swiss-geodesy`);
  - **LV95 tile corners** (`.MinE/.MaxE/.MinN/.MaxN`) and **tile neighbours by kilometre
    arithmetic** (`new TileId(id.E + 1, …)`): ask the tile key instead (G0c). `TileId.Local(e, n)` /
    `Global(x, z)` (metres from its north-west corner, z south), `Centre`, `Contains`,
    `Neighbour(dx, dz)` (in the tile's local axes), `RingDistance`; and the origin's
    `TileTransform(id)` / `TileToWorld(id, local)` / `TileLocal(id, world)`. Place tile-local points
    with the full transform (`xf * local`): in G2 a tile's frame turns a little against the world's.
    Code that asks an LV95 *source* what lies on a tile (the generator's lines, plans, lattices) takes
    the tile's `Lv95Box` or `Touches(minE, minN, maxE, maxN)`; a range of tiles is a `TileRect`
    (`Tiles()`, `Bounding`), next to `TileId` in `tools/TerrainFormat`. LV95 differences are exact
    (Sterbenz), so a reach test moved into local metres gives the same bits.
    `TileKeyTests` pins each to the arithmetic it replaces.
