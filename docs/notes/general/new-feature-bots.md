# Every new thing a player can do, use or meet is decided for bots too

Bots ([#837](https://github.com/SuperQuentin/UnitSportSwitzerland/issues/837), `docs/notes/bots/`) are
players that the **server** runs. They fill Battle Royale matches first, and other modes later
(free-roam PvP, races, co-op). A bot has a body like any player, but no client, no keyboard and no
screen. A feature that only works through a client's input and RPCs is a feature bots cannot use, and
fixing that after it ships means re-plumbing it.

Before a feature is done, go through this list and write the answers down in the same change:

1. **Intent, not input.** Gameplay never reads `Input` where it acts. Input is read in one place and
   becomes an intent the body consumes:
   - moving: `FootPlayer.WalkControls` (wish, run), `FootActions` (jump, crouch);
   - mounts and vehicles: `FootPlayer.RideControls` (`RideInput`), flying: `FlyControls`. A new mount or
     vehicle says what each field means for it, and drives only from it;
   - items: an entry point that takes the player and the intent (`ItemController.UseSlot(player, slot)` is
     the shape), never a key read inside the item's effect. A bot uses items through `BotIntent.FireAt`
     and `Bots/BotHands`, which apply the item's rules on the server: give a new item's use a method
     `BotHands` can call.

   Race NPCs drive cars this way (`RaceNpc` → `AutoPilot` → `RideControls`), and so does the collision
   matrix (`--collidecheck`).
2. **A server path for every client request.** An action that a client asks the server for by RPC
   (loot, open, enter, buy, revive, place) keeps its rules and checks in a server method the RPC calls.
   A bot calls the same method directly. Never put the checks in the RPC handler alone, and never only
   on the client. Never `RpcId` an id that may be a bot's: a negative id means "every peer but that
   one" to Godot.
3. **Senses, honestly.** Anything a player can see or hear that should matter to a bot (a sound, a
   threat, a pickup, a hazard) is published where a bot's senses can read it: an item event the server
   relays, a replicated state, a server list. Give it a range a player could perceive it at. A brain
   never reads the world directly.
4. **The server's collision.** The server builds collision only round bots (`bots/server-collision`): the
   ground, roads, buildings, tunnels and tree trunks of the chunk build. Something solid that only a
   client builds (a prop, a door, a structure) is something a bot walks through: build it from data the
   server has, or name it as a gap.
5. **Skill and brain.** Say which skill handles it (`MoveTo`, `Engage`, `UseItem`, `Loot`, `Drive`,
   `Follow`, `Revive`...) and which brains use it (BR first; PvP, race and co-op later).
6. **Write it down.** Add or update its row in `bots/bot-capability-map`, with the status ok, gap (name the
   target) or n/a. The PR says what a bot would need, and lists any gap under "not done".

**Why:** VR was added after the fact and about twenty actions had no VR way (#440). Bots would hit the
same wall with every input-only or client-only feature.
