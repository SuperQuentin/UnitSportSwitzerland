# Every new thing a player can do, use or meet is decided for bots too

Bots ([#837](https://github.com/SuperQuentin/UnitSportSwitzerland/issues/837)) are players that the
**server** runs. They fill Battle Royale matches first, and other modes later (free-roam PvP, races,
co-op). A bot has a body like any player, but no client, no keyboard and no screen. A feature that only
works through a client's input and RPCs is a feature bots cannot use, and fixing that after it ships
means re-plumbing it.

**Early version.** #837 is not built yet. Until it lands, these two points apply, because they need
no bot code:

1. **Intent, not input.** Gameplay never reads `Input` where it acts. Input is read in one place and
   becomes an intent the body consumes:
   - moving: `FootPlayer.WalkControls` (wish direction, run);
   - mounts and vehicles: `FootPlayer.RideControls` (`RideInput`). A new mount or vehicle says what each
     `RideInput` field means for it, and drives only from it;
   - items: an entry point that takes the player and the intent (`ItemController.UseSlot(player, slot)`
     is the shape), never a key read inside the item's effect. #837 adds an `ItemControls` seam for aim,
     fire, reload, use, switch and interact.

   Race NPCs already drive cars this way (`RaceNpc` → `AutoPilot` → `RideControls`), and so does the
   collision matrix (`--collidecheck`).
2. **A server path for every client request.** An action that a client asks the server for by RPC
   (loot, open, enter, buy, revive, place) keeps its rules and checks in a server method the RPC
   calls. A bot calls the same method directly. Never put the checks in the RPC handler alone, and never
   only on the client.

**Write it down:** the PR says what a bot would need for the feature and whether these two points
hold. When they can't be met, say so under "not done".

**When #837 lands**, this note grows into the full checklist: senses (what a bot can see or hear of
the feature, never an omniscient read), the server's collision around bots (no client-only colliders),
the skill and brain that use it, and a row in `bots/bot-capability-map` with an ok / gap / new status,
like `xr/vr-action-map` for VR (`general/new-action-three-devices`).

**Why:** VR was added after the fact and about twenty actions had no VR way (#440). Bots would hit the
same wall with every input-only or client-only feature.
