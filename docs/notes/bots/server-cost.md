# What a bot costs the server, and why the server draws nothing for its bodies (#842)

- **Rule**: the dedicated server builds no figure mesh for a body it runs. `FootPlayer.ApplyFootPose`
  skips the `_walker.Mesh` rebuild and the face (`StepFace`) when `NetworkManager.DedicatedServer`.
  Clients rebuild their own copy from the replicated pose (`NetPose`, `PoseKind`, `Anim`), which
  `PublishFootPose` writes from state, not from the mesh.
  - The hand's mounts (`PlaceHand`, joint math) are still placed: what a bot holds stays exact.
  - Hits on the server use a cylinder (`PlayerHits.RayCapsule`), never the mesh.
  - A bot's shot leaves from its eye when it has no hand (`ItemEvents.MuzzleOf`).
- **Why**: a walking figure's stride phase changes every frame, so the figure was rebuilt every frame on
  the server. That cost 0.8 ms and 180 KB per bot per frame, the whole of a bot's cost (`--botprofile`).
- **Measured** (`--server --bots N --serverstats`, free roam, Riddes, real tiles):

  | bots | busy p50 before | busy p50 after | gen-0 GCs per 5 s before | after |
  |---|---|---|---|---|
  | 0 | 1.4 ms | | 0 | |
  | 8 | 8.1 ms | 1.4 ms | 64-73 | 0-2 |
  | 20 | 17.2 ms (over a 60 Hz frame) | 2.5 ms | 160-164 | ~1 |

- **`--botprofile`** (`Bots/BodyProfiler`): a server prints `[botprofile]` every 5 s, with each block of
  a bot body's frame in ms and bytes per bot per frame. The blocks are physics, deck, void, separate,
  health, walk, process, wade, publish, pose, deck2 and brains. After the fix: physics ~0.2 ms (walk
  0.14 with `MoveAndSlide`, separate 0.06 and ~450 B for the overlap scan), process 0.03 ms, brains
  ~0.002 ms.
- **Left**: the overlap scan's allocation (`SeparateFromPlayers`), and the road collision cells of a
  generated town, 47-83 ms each to commit, one piece each (`server-collision`).
