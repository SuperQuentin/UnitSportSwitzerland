# Player ids: saved data by who a player is, names looked up when shown (#1359)

- **Rule**: nothing a server saves is keyed by a player's name. A name is typed, deduplicated per session ("Anna2"),
  and changed with `/name` or on the website; keying by it lost money and buildings on a rename and let anyone take
  them (and admin rights) by joining under that name. A stored name is only a cache for a player who is away.
- **`Net/PlayerIds`** (server, no Godot, `PlayerIdsTests`), `PlayerIds.Server`, wired in `ServerWorld`:
  - `IdOf(peer)`: `acct:<user id>` when the server checked the player's account (`AccountGate`, optional or required),
    else the proven PlayerKey fingerprint (`net/sleepers`), else `bot:<name>` for a server-run bot. **Null while a
    player is not proven yet**: a system saves nothing under it and refuses the action for that moment.
  - `NameOfId(id)`: the online player's name now, else the last one seen, else "Rider". It also takes a raw
    PlayerKey (sleepers are keyed by it), found for a signed-in player too.
  - The cache is `user://players/names.json` (`PlayerIdsCache`), id to the last name, written off the main thread.
  - `Identified (peer, id, name)` fires once per session, when the peer has both its id and its chosen name (the
    proof and the name request race on join; `Refresh` is called on both).
- **Old save files** keyed by name: each system's `ClaimLegacy` moves what is still under that name to the id on
  `Identified`, if the id has nothing of its own yet. `PlayerIds.IsId` tells an id key from a name key (a name is at
  most 20 characters). Claimed once, the data follows the id whatever the player is called later. The claim itself
  trusts the name once, as the old code did every time.
- **Admins** (`PlayerRegistry`): `user://admins.json` is `{ids, names}`; a name never grants rights. `/admin add <name>`
  finds an online, identified player (or the one id last seen under that name) and stores its id. An old file's names
  stay in `names` until their player is next identified.
- **Signed in and offline are two identities** on an `--accounts optional` server: the same person's offline
  PlayerKey data does not follow them into their account.
- **Systems on it**: bank accounts, placed objects, structures, farm stands and contracts, BR careers, pinball high
  scores, adventure trials (live names), festival crews, sleepers' tags, admins. The Nakama scoreboard follows the
  same rule on its side (`net/nakama`).
