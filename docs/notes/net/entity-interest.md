# Entity interest: a vehicle, item or radio exists on a peer only where it could be seen (#689)

- **What changed.** Before, `VehicleManager`, `DroppedItems` and `RadioManager` spawned every
  entity on every peer, however far away it was: a client held every car parked anywhere in the
  country. Now the server's `Net/EntityInterest` (at `World/EntityInterest`) decides once a second
  which peer has which entity. Players keep their own vision interest (`vision-interest`).
- **The rules** are pure, in `Net/EntityInterestRules`, and tested in tier 0:
  - **Range.** The entity is sent while it would be `MinPixels` (1.5) wide at the peer's own
    lens (`InterestService.ViewOf`: the reported far plane and FOV). That is about 2.2 km for a
    car and 18 km for an A320. A vehicle's size is the largest side of its parked box. A dropped
    item is sent within 120 m (drawn to 90 m), a radio within 300 m. Everything within 150 m is
    always sent.
  - **Hysteresis.** An entity enters at R and leaves at 1.25 R.
  - **Look-ahead.** The viewer is judged from the nearer of where it is and where it will be
    2 s on, along its last second's travel. A jump faster than 400 m/s is a teleport and gets no
    look-ahead.
  - **Spawn budget.** At most 32 new entities per peer per round, nearest first, so a join or a
    teleport does not burst.
  - **Spatial search.** Entities up to 8 m (`CellSize`) are found through 1 km cells round the
    viewer. Bigger ones (lorries, ships, aircraft) are checked against every viewer.
- **No pop.** On a client, a remote vehicle's meshes get `VisibilityRangeEnd` = 0.8 R, with a
  0.1 R margin and `FadeMode.Self` (`VehicleBody.FadeAtRange`). The node arrives at R while
  still invisible and fades in. It is fully gone by 0.9 R, long before the despawn at 1.25 R.
- **The synchronizers** (`Net/EntityNet.Add`), the same on every peer so that node paths match:
  - **`Vis`.** Server-owned and empty. It decides spawning: the authority, or `Exists`.
  - **`Relay`.** Only when a client owns the entity. It is the server-owned copy of the owner's
    `Sync`, filtered by `Sends`.
  - **The owner's `Sync`.** It gets the filter `peer == 1`: the owner sends to the server only,
    as players do.
  - **Server-owned entities.** For an entity the server owns, `Sync` itself is filtered by
    `Sends`. So is a radio's `State` (passed as `serverOwned`).
  - **How Godot combines them.** Godot composes spawn visibility as the **OR** of the
    server-owned synchronizers. So the owner always has its own entity, and `Relay`, which
    excludes the owner, cannot hide it.
  - **Update mode.** Every filtered synchronizer has `VisibilityUpdateMode.None`, and
    `EntityNet.Refresh` calls `UpdateVisibility(peer)` when a set changes
    (`perf-visibility-on-change`).
- **Leaving.** The stream stops first (`Sends` goes false at once). The node goes 0.4 s later,
  when `Exists` goes false, so a packet already in flight never meets a missing node.
- **Spawned already in range.** `EntityNet.Add` calls `EntityInterest.Admit` from the entity's
  `_Ready`, so a thrown can is on nearby peers from its spawn, not one round later.
- **Relay rate.** The server re-rates each client-owned `Relay` every round (`RelayRate`):
  0.05 s while the entity moves, 2 s once it rests.
- **Prediction.** A third peer's prediction of a fall stops on `Relay.Synchronized`
  (`DroppedItem`), because the thrower's updates now come through the server.
- **Dormant slots.** With interest, a woken car that was driven away does not exist on a far
  peer, so the old rule ("the copy goes when the node appears") would draw it back in its bay.
  `DormantVehicles` therefore sends the awake set to everyone:
  - **On join**, the whole set (`SendTo`).
  - **On each wake**, a broadcast (`Woke`).
  - **The copy waits** up to 1 s for the node (3 s on joining) before the bay empties, so a
    near peer never sees an empty frame (`dormant-vehicles`).
- **Check.** `tools/containernetcheck.sh` (tier 2):
  - B sees A's client-owned car and item;
  - from 5 km away, B has no vehicle or item at all;
  - back at the lot, B has them again in the same place, with the same oid.
- **Not done.**
  - Line of sight: entities are judged by distance only.
  - Radios: still a fixed 300 m.
  - Fading items: not needed, because the item range is larger than the item draw range.
