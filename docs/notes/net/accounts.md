# Accounts: offline or online players, servers that require, allow or ignore an account (#1123)

## Client: two modes (Settings › Account, `src/Ui/AccountPage.cs`)

- **Offline** is the default and is how the game was before #1123. There is no account: the install's
  `PlayerKey` is the only identity (`net/sleepers`).
- **Online** means signed in to an account server, a Nakama (`net/nakama`).
  - **The page**: signed in, one card ("Signed in as …", Sign out). Signed out, two choices: **I have an account**
    (email, password, Sign in) and **New account** (plus a name for the scoreboards, Create account).
  - **The official account server** is `res://assets/account-server.json` (`url`, `serverKey`):
    `https://unitsport.infrack.ch/nakama` since #1205, Nakama behind the site's Caddy. `tools/deploy-linux.sh --nakama`
    prints both. The server key is not a secret. Players never type it:
    **Advanced** sets another server, folded away, and opens by itself while the build names none.
  - The player sets its address (`http://host:7350`) and server key (not a secret), then signs in by email and
    password, or creates the account with an optional name for the scoreboards.
  - The password is never stored. Sign-in keeps the session and refresh tokens in **`user://online_account.json`**
    (`Net/Accounts/Account`), apart from `settings.json`, so tokens never travel with a shared settings file.
    It is not `user://account.json`: that one is the offline bank's (`items/cash-account`).
  - **Sign out** forgets them. Changing the account server forgets the session of the old one.
- `Account.TokenFor(server)` hands out the session token only to a server whose accounts live on the account
  server the player is signed in to.
  - It refreshes the token when less than a minute is left. A session token lasts a day and a refresh token
    30 days (`tools/nakama/local.yml`).
  - It returns "" when offline, signed in elsewhere, or unable to renew.

## Server: `--accounts off|optional|required` and `--nakama-url <url>`

- **Deploy**: `ACCOUNTS=optional|required` in `tools/deploy.env` adds `--accounts … --nakama-url $NAKAMA_URL` to the
  server's start line. `NAKAMA_URL` defaults to `http://<DEPLOY_HOST>:7350`, the address players type
  (`general/linux-deploy`).
- **off** is the default, and is used by every other net check and by servers hosted from the menu. The account
  step admits at once.
- **optional**: a player signed in to this server's account server joins with the account checked; any other
  joins as an offline player. A token that fails the check also joins offline: the account is a bonus here,
  never a lock.
- **required**: only a checked account joins. Any other player is refused with a sentence that points to
  Settings › Account (`AccountRules.Refusal`).
- A mode other than off with no `--nakama-url`, or an unknown mode, stops the server at start with the reason,
  before any world loads.

## The account step (`Net/Accounts/AccountGate`, `World/Accounts`, protocol 49)

- It runs right after the version check (`Handshake`), whose RPCs never change.
- With `off`, the server sends `Welcome("")` at once.
- With `optional` or `required`:
  - the server sends `Ask(mode, url)`;
  - the client answers `Present(token)`, an empty token when it has none;
  - the server checks the token by **reading that player's account with it** (`GET /v2/account`,
    `NakamaRest.Account`). A game server therefore holds no Nakama secret at all;
  - the server then sends `Welcome(account name)` or `Refuse(reason)`, followed by a disconnect after 0.3 s, as
    the version check does.
  - A peer that presents nothing within 20 s is decided as offline.
- **The client joins for real only on `Welcome`** (`ClientWorld.OnWelcomed`: its name request, the host claim
  and the terrain sync). On the server, `OnPeerAccepted` (registry, spawn, world state) runs on `Admitted`.
  Nothing from a refused peer is ever acted on.
- **On the server, `AccountGate.Of(peer)`** gives the checked `NakamaAccount` (user id, name), or null for an
  offline player. Race results posted under a player's account (`net/nakama`, deliverable 4 of
  `docs/plans/trainer-edition.md`) use it. The plan's open point is settled: a player's session comes from their
  own sign-in, never from the public PlayerKey fingerprint.
- **Not yet**:
  - the display name still comes from the player's own request (`PlayerRegistry`), not from the account;
  - the server list does not show a server's mode before joining, and a refusal is the first a player hears of it.

## Checks

- **Unit**: `AccountRulesTests` covers mode parsing, the admit rules, the address spelling and the token
  expiry.
- **Net**: `tools/accountnetcheck.sh` runs on a throwaway Nakama (`tools/nakama/throwaway.sh`, ports 17360 and
  17361), so **it needs Docker**.
  - `required` refuses an offline client (`--accountprobe refuse`) and admits a signed-in one
    (`--account-email/--account-password/--account-url/--account-key`, an in-memory sign-in that creates the
    account, `--accountprobe admit`).
  - `optional` admits the offline client.
  - `--accountprobe admit:<name>` also checks the account name.
