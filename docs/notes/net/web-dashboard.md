# Website accounts and the admin dashboard (#1207, #1211, `docs/plans/web-dashboard.md`)

## Accounts on the site

- **`tools/deploy/web/account.js`** gives the site the same Nakama accounts as the game, through `/nakama/`
  (`net/nakama`).
  - **Placement**: a page puts `<div data-account></div>` where the control goes and loads the script. `index.html`
    and `admin.html` do.
  - **The control**: "Sign in" opens a dialog with two tabs. **Sign in** asks for email and password. **Create
    account** adds a name in the game: 2 to 20 letters, digits, `-` and `_`, or empty to let Nakama pick one.
  - **Signed in**, it shows the name, **Dashboard** for an admin, and Sign out.
- **The server key** comes from `nakama.json`, which `--nakama` writes beside the pages. It is not a secret.
- **The session** (Nakama's token and refresh token) lives in `localStorage`, under `unitsport.session`.
  - It is renewed a minute before it runs out.
  - Sign out calls `/v2/session/logout`.
- **`window.UnitSportAccount`** exposes `ready`, `me()`, `onChange`, `rpc(id, payload)`, `token()`, `signOut()` and
  `open()`.

## Admins

- **An admin is a member of the Nakama group `admins`.**
- **The first admins are bootstrapped by email.**
  - `NAKAMA_ADMIN_EMAILS` in `tools/deploy.env` (default: `LAYOUTS_ADMINS`) goes into the host's Nakama `.env`, and from
    there into the module's runtime env as `ADMIN_EMAILS`.
  - An account with one of those emails joins the group on its first `me`. The first one founds the group, which is
    closed: nobody can ask to join it.
- **The module checks every admin RPC itself.** The page only hides the button. `me` is
  `{id, username, email, admin}`.

## The dashboard (`admin.html`)

- **Users tab**:
  - Search by name or email: `admin_users {q}`, a SQL `ILIKE` over `users`, 50 newest. `%` and `_` typed by the admin
    match themselves.
  - Open an account: `admin_user {id}`.
  - **Make admin / Remove admin**: `admin_set_admin {id, admin}`. An admin cannot remove their own rights.
  - **Ban / Unban**: `admin_ban {id, ban}`, which uses `nk.usersBanId`. The page asks for a second click before a ban,
    and an admin cannot ban themselves. A banned account cannot sign in ("User account banned."), its sessions end, and
    servers that check accounts refuse it.
- **Server tab** (#1211):
  - the server's name, version, uptime, players and account mode, live every 5 s;
  - **Update** (`/update`) and **Restart** now or in 1, 5 or 10 minutes, asked twice; players are warned in the chat;
  - the world: time of day and day length (`/time set`, `/time speed`), weather (`/weather clear|cloudy|reroll|auto|snow`),
    sea state, simulation speed, a message to everyone (`/say`), each with the line the server answered;
  - the players online: account, ping, position (LV95), **Kick** (asked twice; admins cannot be kicked, as in game);
  - the **startup arguments** (`server-args.local`), saved for the next restart.
- **Console tab**: the server's log live (polled every second), a command line with history; every command runs with
  the console's rights and is logged as `[admin] <name> (website): /<command>`. The chat names the admin too ("Quentin
  changed the weather"), not "Console".
- A non-admin, or someone signed out, sees a gate instead.

## The game server's admin API (#1211)

- **Flags**: `--admin-http <port>` (loopback only) and `--admin-nakama <url>` (else `--nakama-url`). Without a Nakama URL
  the API does not start.
- **Code**:
  - `Net/AdminApi` (no Godot, unit-tested in `AdminApiTests` over real HTTP): routes, the Bearer check, the log ring
    (`AdminLogRing`, 2000 lines, sequence numbers) and the startup-args rule (`StartupArgs`).
  - `Net/LoopbackServer`: the HTTP transport, shared with the playtest MCP endpoint (`Playtest/LoopbackHttp`).
  - `Net/AdminHttp`: the node (`World/AdminHttp`), its Godot `Logger` feeding the ring, every call handed to the main
    thread. `ChatManager.Web`: commands with their replies captured (`RunWebCommand`, `AskQuietly` for the status),
    `KickFromWeb`, `RestartFromWeb`, `WebPlayers`.
- **Auth**: each request's `Authorization: Bearer <Nakama session token>` goes to the module's `me` RPC
  (`NakamaRest.AdminName`); an admin is cached a minute (`AdminApi.CacheFor`). 401 without a token, 403 for a non-admin,
  502 when Nakama does not answer. The page takes the token from `account.js` (`token()`, a promise: renewed first).
- **Calls**: `GET /status`, `GET /log?after=<seq>`, `GET /players`, `POST /command {line}`, `POST /kick {peer, reason}`,
  `POST /restart {minutes}` (0 to 30), `POST /update`, `GET`/`POST /startup {args}`.
- **Restart**: needs `UNITSPORT_DEPLOY_DIR` (exported by `start-server.sh`). It writes `restart-requested` there, kicks
  everyone and quits; `start-server.sh run` starts the same build again (an `/update` marker wins). Real minutes, not
  `/speed` time.
- **Startup arguments**: `$UNITSPORT_DEPLOY_DIR/server-args.local`, written whole then moved. `start-server.sh` puts them
  **first** on the command line, unglobbed (the game reads the first of a repeated option, so they win). Only letters,
  digits, spaces and `. _ : / , = @ + -`, starting with an option; `--server --port --admin-http --admin-nakama
  --headless` are the deploy's. A deploy never writes the file.
- **The log** holds what was logged since the API started (the boot's first lines are only in `server.log`); after a
  restart the page notices the sequence went back and reads from the start.

## Deploy and Caddy

- **Caddy** serves `/admin.html`, `/account.js` and `/nakama.json` (`no-store`), and `/server-api/*` (prefix stripped,
  body up to 64 KB) to `127.0.0.1:ADMIN_HTTP_PORT` (7790).
- **`--nakama`** uploads `account.js` and `admin.html`, writes `nakama.json`, and sets `NAKAMA_ADMIN_EMAILS` in the
  host's `.env` (through sudo).
- **A full deploy** uploads the two pages with the others too.
- **`DASHBOARD=1`** (the default with a web site) adds `--admin-http ADMIN_HTTP_PORT --admin-nakama http://127.0.0.1:NAKAMA_PORT`
  to the server's arguments; Caddy's `/server-api/` needs `--setup` once.

## Checks

- `tools/nakama/check.sh`:
  - a player's `me` says not admin, and `admin_users` gets 403;
  - the bootstrap email becomes admin;
  - search finds an account;
  - make and remove admin; removing one's own rights gets 400;
  - a ban makes sign-in fail, and an unban restores it.
- **A browser run** (Edge through `playwright-core`, against a throwaway Nakama behind Caddy in Docker):
  - sign up as a player: no Dashboard button, and `admin.html` shows the gate;
  - sign up as the bootstrap admin: the Dashboard button;
  - search, open, make and remove admin, ban (the banned player's sign-in shows "User account banned."), unban;
  - the dashboard at phone width.
- **`tools/adminhttpnetcheck.sh`** (net, needs Docker): a throwaway Nakama, a server with the API and a joined client;
  401 and 403, status, `who` and `say` with the admin's name in the log, the players, the startup file saved and
  `--port` refused, a kick by peer, and a restart that quits and leaves the marker.
- **A browser run** of the Server and Console tabs (Edge, a Node proxy standing in for Caddy, a real server and client):
  live status, weather with its broadcast, say, startup saved, `who` in the console, kick, phone width.
