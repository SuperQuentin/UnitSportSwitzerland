# GPX picker on Android: the system document picker (#1027)

- **Why not the filesystem:** on Android 10+ (scoped storage) an app sees none of the shared storage through `System.IO` or Godot's own `FileDialog`, and asks for no permission that would change that short of `MANAGE_EXTERNAL_STORAGE`, which a game should not request. The old Browse listed nothing.
- **Browse on Android** is `FileDialog { UseNativeDialog = true }`: Godot opens `ACTION_OPEN_DOCUMENT` (Storage Access Framework, `FilePicker.kt`). The user picks anywhere (Downloads, Drive, a file manager), no permission, and Godot hands back `content://` URIs.
- **No filter on Android:** Godot maps a filter to a MIME type, and file managers often record a .gpx as `application/octet-stream`; an `application/gpx+xml` filter would hide those. `GpxPicker.Import` refuses what does not start with a `<gpx` element instead ("Not a GPX track").
- **Copied in:** `GpxPicker.Import` reads the URI with `Godot.FileAccess.GetFileAsBytes` (Godot's Android `FileAccess` reads `content://`, `StorageScope`) and writes it to `user://gpx/<name>.gpx`. The name is the URI's last segment (`primary%3ADownload%2Fride.gpx` → `ride.gpx`). The same bytes picked twice are kept once; a different file of the same name becomes `name (2).gpx`. The track is then listed like any in the folder and replays offline.
- **"Open folder"** is hidden on Android: `user://` is private to the app.
- **Checked** on the API 34 emulator (`core/android-emulator`): a GPX pushed to `/sdcard/Download`, Browse → Downloads → tap → listed and ticked → Start replay loads it (`[gpx] +riddes-test-ride: 300 pts`).
