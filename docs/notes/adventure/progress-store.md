# The adventure progress store: one file per player, a section per system (#1223)

`src/Adventure/SectionKey.cs` and `PlayerProgress.cs`: plain C#, no Godot, linked into the unit tests
(`AdventureBookTests`).

## Rule

- **A system declares its section in its own file**, never in a central list:
  `public static readonly SectionKey<PlacesProgress> Section = new("places", Version: 2, Migrate: ...);`
  The id is a stable lower-case JSON key; `T` a plain DTO (`class, new()`) serialized with
  `AdventureJson.Options` (camelCase, one static instance). Reserved ids: `quests` (this plan),
  `places`, `fog`, `travel`, `pins`, `stamina`, `collect`, `chests`, `trials`, `photos`, `gadgets`.
- **Read with `progress.Get(Section)`, write the object, then `progress.Touch(Section)`** (or
  `AdventureService.Touch(peer, Section)`). A change without `Touch` is neither saved on time nor sent
  to the owner: `PlayerProgress.Untouched()` finds it (tests), and every save logs
  `section 'x' changed without Touch` for it.
- **Bump `Version` and give `Migrate: (JsonNode old, int from) => ...` when a shape changes.** A section
  migrates itself on first `Get`, and is written back in the new shape at the next save.
- Never key progress by the name a player types: the service keys it by the proven identity
  (`service`).

## The file (`AdventureBook`)

```json
{ "v": 1, "key": "9f2c...", "name": "Lea", "created": 1793000000, "seen": 1793004000,
  "sections": { "quests": { "v": 1, "data": { ... } }, "places": { "v": 2, "data": { ... } } } }
```

- The envelope's `v` covers the envelope only; each section has its own `v`.
- `AdventureBook.FileName(key)` keeps letters, digits, `-` and `_` (`acct:abc` -> `acct_abc.json`).
- One player per file, loaded on join and unloaded on leave (`Forget`): fog alone may be KBs.

## Same data, whatever the build

- **A section no running code asked for** (a system off under `--systems`, a newer build's) stays raw
  JSON and is written back byte for byte: a run never loses another system's progress.
- **A section saved by a newer version** than this build's is kept raw too; `Get` returns a read-only
  empty value with a warning, and `Touch` on it is refused (a downgrade never overwrites newer data).
- **An unreadable section** (a shape that does not deserialize) is kept raw and read as empty, the
  same way. An unreadable *file* is copied to `<file>.unreadable` before fresh progress replaces it.

## Dirty, sync and save

- `Touch` sets two flags per section: saved (`NeedsSave`, `Saved()`) and synced (`NeedsSync`,
  `TakeSync()`). The service sends synced ids at most 4 times a second and saves at most every 5 s
  (`service`).
- The client's mirror (`AdventureService.Mine`) is a `PlayerProgress` too: `SetRaw(id, version, json)`
  on each `SectionSync`, decoded again on the next `Get` by the same `SectionKey`.

## How to check

`tools/test.sh unit` (`AdventureBookTests`: round trip, unknown and newer sections kept, v1 -> v2
migration, lazy decode, dirty set, the untouched detector, the mirror, file names).
